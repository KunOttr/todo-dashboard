使用帮助

这是什么

一个把 GitHub Issues 当待办库的纯前端管理面板：每条待办就是一个 Issue，通过 GitHub GraphQL API 读写；可静态部署到 GitHub Pages，无需后端。

开始使用

  1. 准备 Personal Access Token：fine-grained PAT 仓库访问选目标仓库、Issues 权限设为 Read and write（Metadata: Read 自动附带）；经典 PAT 私有仓库用 repo、公开仓库用 public_repo。Gitea 仓库用 Gitea 的 Access Token（需仓库读写权限）。
  2. 点右上角「设置」→「+ 添加仓库」，选择 API 格式（GitHub GraphQL / Gitea REST），填写 仓库 URL（自动识别 owner / 仓库名，Gitea 会同步识别服务器地址）、Token，并勾选该仓库是否支持百分比进度；保存第一个仓库后会自动连接。
  3. GitHub Enterprise：支持 Enterprise Cloud（与公开版共用 api.github.com，直接填 https://github.com/owner/repo 即可）与 自建 Enterprise Server（填 https://你的域名/owner/repo，面板会自动拼接 /api/graphql 作为 GraphQL 端点；也可在「服务器地址」输入框里手填 GHE 域名）。
  4. 支持 Gitea 官网（gitea.com）或任意自建 Gitea 实例，粘贴仓库 URL 即可。
  5. 自建 Gitea 需开启 CORS：在服务器 app.ini 的 [cors] 段设置 ENABLED = true、ALLOW_DOMAIN = *（METHODS 需含 OPTIONS），修改后重启 Gitea；否则浏览器跨域预检（OPTIONS）会被拒绝，表现为「连接失败」。
  6. 可精确限定来源：ALLOW_DOMAIN = 192.168.1.*, *.example.com（按正则匹配 Origin，支持局域网与子域名）。若预检返回 200 但仍报 CORS error，说明 Origin 未匹配——本地用 localhost/127.0.0.1 打开页面时需把它们加入列表；用 file:// 直接打开时 Origin 为 null，需额外加 null（建议改用 HTTP 静态服务打开）；部署在 GitHub Pages（https://用户名.github.io）时需把该域名加入列表。若 Gitea 前有反向代理，需在代理层同步放行 CORS 头。
  7. 页面为 HTTPS 时 Gitea / 自建 GHE 也必须是 HTTPS：浏览器禁止 HTTPS 页面请求 HTTP 接口（混合内容，报 mixed block）。部署在 GitHub Pages 等 HTTPS 站点时，请为 Gitea / GHE 配置 HTTPS 并使用 https:// 的服务器地址。
  8. Token 使用 AES-GCM 加密后存在浏览器本地，输入框不回显旧值、编辑留空即保留原 Token；「记住 Token」默认开启（下次打开自动解密），关闭它则关闭浏览器后需重新输入，安全性更高。纯前端方案无法彻底防住本地恶意软件 / 浏览器扩展窃取，请使用权限最小化的令牌并避免在公共设备使用。
  9. Token 只保存在浏览器 localStorage 中，请勿在公共/共享设备上使用。

待办与状态

  • 每条待办 = 一个 Issue；已完成 / 未完成 对应 Issue 的关闭 / 打开状态。
  • 「未完成」在上方（按创建时间倒序，最新在上）；「已完成」在下方（按完成时间倒序，最近完成在上）。
  • 点击卡片左侧勾选按钮：未支持百分比的待办点击直接切换完成状态。
  • 描述较长时卡片默认只显示 3 行，点击下方「显示全部」可展开查看完整内容，再次点击「收起」折叠。

百分比进度（按仓库启用）

  • 是否支持百分比是每个仓库单独设置的（添加 / 编辑仓库时勾选）。
  • 支持百分比的仓库，新建待办可勾选「支持百分比」；该待办用圆环展示进度。
  • 点击圆环弹出 0%–100% 滑动进度条；100% 自动标记完成，调低自动回到进行中。
  • 关闭某仓库的百分比时，该仓库进行中待办将回退为未完成并丢失进度（编辑仓库时有确认提示）。

新建与编辑

  • 点操作面板「+ 新建待办」，在顶部出现编辑卡片：输入标题 / 描述、可勾选支持百分比；点「保存」生效，点「取消」丢弃。
  • 每张卡片标题下方一行最左侧有「+ 标签」按钮：点开直接勾选标签，保存后立即生效并实时同步，无需进入编辑模式（新建待办保存后也可用此按钮补加标签）。
  • 点卡片「编辑」后，原卡片隐藏、仅显示编辑卡片；编辑卡片支持修改标题 / 描述、进度与「归档 / 删除」操作。
  • 先归档再删除：未归档的待办显示「归档」（红色），归档后按钮变为「删除」（红色，需确认）。

筛选与搜索

  • 操作面板默认一行：左侧「筛选」（展开 / 收起筛选选项）、搜索框、「同步」按钮（有未同步改动时才显示），右侧「新建待办」。
  • 筛选选项：时间（按创建 / 完成时间，起始结束可只填其一）、标签（多选，支持「任一 / 全部」）、「显示归档」开关。
  • 关键词搜索匹配标题、描述、标签名，与其它筛选条件叠加生效（与关系）。
  • 归档任务默认隐藏；在标签筛选中选中「归档」标签会联动打开「显示归档」。

多仓库

  • 设置中可添加 / 编辑 / 删除多个仓库；顶部下拉切换当前仓库（当前项带 ✓ 标记）。
  • 每个仓库可选择 API 格式（GitHub GraphQL 或 Gitea REST），支持粘贴自定义仓库 URL（如 Gitea 自建实例、自建 GitHub Enterprise）；各仓库独立配置 Token 与是否支持百分比。

标签管理

  • 「标签管理」按钮位于顶部左侧（仓库切换按钮旁边）。
  • 全局标签管理中，系统标签（归档、进度:*）默认折叠、只读；普通标签可标记删除（点「删除」置顶变灰、可「恢复」），点「保存」统一删除。
  • 给单个待办选标签时只显示普通标签（不含系统标签、无删除按钮）。

自动同步（防限速）

  • 所有操作先在本地生效并排队，距最后一次操作 5 分钟后自动批量保存到 GitHub。
  • 「同步」按钮显示待同步数量与剩余倒计时，点击立即保存。
  • 关闭页面前若仍有待同步改动可能丢失，建议留意同步按钮或主动点击保存。

部署到 GitHub Pages

生产构建：仓库自带 esbuild 合并压缩流水线。npm install 后执行 npm run build，生成 dist/（index.html + 带内容 hash 的 style.min.*.css / app.min.*.js，共 3 个文件）。部署单元是 dist/，源码不直接上线。

部署方式任选其一（不强制使用 workflow）：方式 A（推荐）——手动 npm run build 后提交 dist/，在 Settings → Pages → Deploy from a branch 指向 /dist 目录；方式 B（可选示例）——把 .github/workflows/pages.example.yml 重命名为 pages.yml 并推送，Actions 会自动 npm ci → npm run build → 上传 dist/ 发布。页面地址为 https://<用户名>.github.io/<仓库名>/。

如需本地预览：npm run serve（构建后用静态服务器打开 dist/）。
