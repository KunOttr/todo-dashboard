# TodoDashboard 功能路线图（v2 · 个人+周度场景）

> **重要前提变更**：TodoDashboard 定位为**个人**本地优先 todo 工具，核心使用场景是**一周工作进度管理**。这一定位决定了 P1/P2 优先级与原 v1（v1 隐含团队协作场景）相比有大幅调整。
>
> 方法：先刻画"个人一周"的使用画像 → 列出三平台通用能力（交集）→ 按画像匹配功能 → 重排 P0/P1/P2。

---

## 一、个人周度使用画像

TodoDashboard 用户的典型一周：

| 时点 | 行为 | 触发的功能需求 |
|---|---|---|
| **周一早上** | 列出本周重点 → 批量创建 todo | 快速创建、模板复用 |
| **周内任意时刻** | 录入临时事项、改优先级、勾选完成 | 截止日期、优先级、状态切换 |
| **周四/周五** | 复盘进度、调整剩余 todo 的截止日 | 进度可视化、本周视图 |
| **周末** | 看这周完成了什么、什么顺延到下周 | 周回顾摘要、归档 |
| **任意时点** | 查找某条老 todo、按标签过滤 | 搜索、标签过滤、时间筛选 |

**核心特征**：
- **单人**——不需要多人协作（assignee、@mention 等团队语义价值低）
- **周度节奏**——核心时间单位是"本周"，不是项目 milestone
- **本地优先**——敏感/个人 todo 不应离开浏览器
- **轻量录入**——操作要快，不能打断思路

## 二、三平台通用能力（交集 ✅✅✅）

以下功能在 GitHub / Gitea / GitLab **全部原生支持**，可安全接入：

| 能力 | 字段 / 端点 | 个人+周度场景用途 |
|---|---|---|
| 标题 | `title` | todo 主标题 |
| 正文 | `body` / `description` | 详情、备注、链接 |
| 状态 | `state` (open/closed) | 完成标记 |
| 标签 | `labels` | 分类、优先级、进度、归档、截止日期（模拟） |
| CRUD | POST/PATCH/DELETE | 创建、编辑、删除 todo |
| 评论 | `comments` / `notes` | 自留备注、决策痕迹 |
| 反应 | `reactions` / `award_emoji` | ⭐ 单人场景**价值低**，本版本**不集成** |
| 里程碑 | `milestone` | ⚠️ 单人周度场景用"周标签"代替，不集成原生 |
| 锁定 | `locked` / `discussion_locked` | 归档后冻结讨论（可选） |
| 时间戳 | `created_at` / `updated_at` / `closed_at` | 周回顾、按时筛选（**核心数据源**） |
| 搜索 | `/search/issues` | 关键词快速定位 |

## 五、P1 — 高价值（个人+周度核心场景）

按用户需求强度排序如下：

### P1.1 本周视图 ⭐⭐⭐⭐⭐
- **为什么是 P1**：直接对齐用户需求"一周工作进度管理"。
- **现状**：未集成（当前所有 todo 平铺，只有"未完成/已完成"两栏）。
- **建议**：
  - 顶部切换栏：`今日` / `本周` / `全部` / `已归档`。
  - "本周"定义：基于 `created_at` 在本周一 ~ 本周日+ 的范围（或基于 `due` 标签在本周范围内的）。
  - 实现成本低——纯前端按时间戳筛选，无需新 API。
- **三平台对应**：靠 `created_at` / `closed_at`，全部原生支持。

### P1.2 截止日期 ⭐⭐⭐⭐⭐
- **为什么是 P1**：周度规划离不开"这周要完成什么"。
- **现状**：未集成。
- **建议**：
  - **统一用 `due:YYYY-MM-DD` 标签模拟**（平台无关）。
  - 新建/编辑面板加"截止日期"字段。
  - 列表项显示：`📅 9/10 (剩 3 天)`，剩 1 天变红、超期变粗红。
  - **关键决策**：用 label 而非 `due_date` 字段——因为 GitHub 无原生字段，统一 label 让三平台代码同构。

### P1.3 优先级 ⭐⭐⭐⭐⭐
- **为什么是 P1**：个人 triage 的核心——40+ 条 todo 必须能立刻识别"今天必须做"。
- **现状**：未规范化（虽然标签管理可建，但没规范）。
- **建议**：
  - **统一用 `priority:P0/P1/P2` 标签**（颜色固定：P0 红、P1 黄、P2 灰）。
  - 列表项在标题前显示 chip（`[P0]`/`[P1]`/`[P2]`）。
  - 默认筛选可按优先级排序。

### P1.4 快速创建 ⭐⭐⭐⭐
- **为什么是 P1**：单人高频操作，每周一要批量创建十几条 todo。
- **现状**：新建要打开面板，填写标题+描述+标签，3-5 步。
- **建议**：
  - 快捷键 `n` 或 `c` 唤起快速新建面板（浮层/抽屉，非全屏）。
  - 极简表单：标题（必填）+ 优先级 chip + 截止日期（可选）。
  - 提交后立即关闭，不跳转；连续按 `n` 可连续录入。
  - 复用现有 `pendingOps` 操作队列。

### P1.5 周回顾 ⭐⭐⭐⭐
- **为什么是 P1**：周度节奏的闭环——周五/周末能看到"这周干得怎么样"。
- **现状**：未集成。
- **建议**：
  - 新增"周回顾"视图（或周五时自动弹摘要卡）。
  - 摘要内容：
    - 本周完成 N 个（按 closed_at 过滤本周范围）
    - 本周创建 N 个
    - 本周进度更新次数
    - 已超期未完成 N 个（按 due 标签 + closed_at=空）
    - 顺延到下周建议清单
  - 可选：导出为 markdown（贴到周报里）。
- **三平台对应**：靠时间戳，全部支持。

### P1.6 重复任务（升级自 v1 P2.3） ⭐⭐⭐⭐
- **为什么是 P1**：单人场景反而比团队更需要——周复盘、月度报表、季度总结都是周期性个人任务。
- **现状**：未集成。
- **建议**：
  - 在 TodoDashboard 内独立维护"模板库"（**不写死到 issue**，避免污染 repo）。
  - 模板结构：`{title, body, labels, priority, due, milestone}`。
  - 创建 todo 时可"从模板创建"，自动填充字段。
  - 可选：每周一自动从"周复盘"模板创建一条 todo（前端 `setInterval` 或手动）。
- **关键决策**：模板库是 TodoDashboard 内部数据结构，**不写回 GitHub/Gitea/GitLab**——避免在 repo 里出现一堆重复 issue 污染历史。

## 六、P2 — 探索性（谨慎引入）

> 这些功能价值有限或集成难度高，**延后评估**，等真实使用需求出现后再决定。

### P2.1 父子任务（轻量标签模拟） ⭐⭐⭐
- **场景**：把季度目标拆解成月/日 todo。
- **策略**：标签 `parent:#123` 模拟，列表项可展开查看子 todo。**不接原生 sub-issue API**——三家 API 差异太大，且单人场景拆解频率不高。

### P2.2 自定义字段 ⭐⭐
- **场景**：某些 todo 需要携带额外元数据（订单号、外部链接）。
- **策略**：`key:value` 标签模拟（如 `order:2024-001`、`link:https://...`）。

### P2.3 评论（自留备注） ⭐⭐
- **场景**：单人在 todo 里留决策痕迹或上下文。
- **策略**：拉评论列表 + 加评论按钮，但**不做通知/订阅**等团队语义。

### P2.4 批量操作 ⭐⭐
- **场景**：周一清空上周末完成 todo 时用得上。
- **策略**：checkbox + 顶部工具栏（批量关闭/加标签），复用 `pendingOps`。

### P2.5 时间追踪 ⭐
- **场景**：记录某任务实际花了多少小时。
- **策略**：**不做**。单人不关心工时，是工单系统的事。

## 八、实施建议（v2 顺序）

**第一梯队（周度核心 flow，必做）**：
1. **P1.1 本周视图**——建立周度入口，所有后续功能都依赖它
2. **P1.2 截止日期 + P1.3 优先级**——同步做，都是标签模拟，UI 改造成本低
3. **P1.4 快速创建**——基于 P1.2/P1.3 的字段，强化录入流

**第二梯队（周度闭环，可选）**：
4. **P1.5 周回顾**——依赖 P1.1（本周视图）和 P1.2（截止日期）的数据
5. **P1.6 重复任务（模板库）**——独立模块，可后置

**第三梯队（按真实需求触发）**：
6. P2.1 ~ P2.5 按需
